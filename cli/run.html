lazyapi run ​

Runs the selected operations of a spec. Each exchange is checked four ways:

  1. request: the request sent must match the operation (required parameters, parameter schemas, body schema). It is still sent when it fails, because the server's answer is useful too.
  2. status: the status code must be declared in the operation's responses (exact code, 2XX-style range, or default).
  3. contract: response headers and body must match the declared schema.
  4. tests: the operation's script (x-lazyapi-tests, or --script). See Test Scripts.

--no-contract skips both the request and contract checks.

bash
lazyapi run <spec.yml> [flags]

Selection ​

FlagDescription
--methods <list>Methods to run. The default is GET,HEAD,OPTIONS; all includes POST/PUT/PATCH/DELETE. Other methods are reported as skipped
--tag <list>Only operations with one of these tags
--op <list>Only these operations, by operationId or "METHOD /path"
--grep <regex>Only operations whose METHOD /path operationId summary matches

Order ​

Operations run in spec order within four groups: reads (GET/HEAD/OPTIONS), then POST, then PUT/PATCH, then DELETE. A run therefore does not delete what later operations read. For exact sequences, use flows.

Flows ​

FlagDescription
--flowsAfter the operations, run every .lazyapi/flows/*.js next to the spec
--flow <file>Run only this flow (repeatable); no operations are run
--flow-timeout <d>Maximum run time of one flow (default 5m)

Flow results appear in the report with "kind": "flow", "method": "FLOW", the flow path, its steps (each with request and response, bodies following --bodies) and its checks.

Data-driven runs ​

--data users.csv (or .json) runs the whole selection, operations and flows, once per row, like Postman's collection runner with a data file:

csv
email,name
ana@example.com,Ana
bia@example.com,Bia
bash
lazyapi run api.yml --op createUser --methods POST --data users.csv
lazyapi run api.yml --flow .lazyapi/flows/signup.js --data users.json
  • CSV needs a header row. JSON is an array of objects; numbers and booleans become text, nested values JSON text.
  • In each iteration the row's values are added to the env: use {{env.email}} in params, headers and bodies (--param id={{env.id}}) and env.get("email") in scripts. Imported Postman {{email}} placeholders already read the env.
  • Every iteration starts from the same env and vars: what a script sets in one row does not leak into the next.
  • Scripts see lazyapi.iteration (0-based) and lazyapi.iterations.
  • Results carry "iteration" (1-based) and labels end with [#n] in every output format; the report has "iterations". --bail stops after the iteration with the first failure. At most 10 000 rows.

Execution ​

FlagDescription
--env-name <name>Named environment from .lazyapi/config.yml: server, env file, vars and credentials
--server <url|index>Server URL, or index into the spec's servers (default: first). Wins over the environment
--env <file>.env file for {{env.NAME}}. Wins over the environment
--param k=vPath parameter for operations that declare it (repeatable). Otherwise the spec's example is used; with no value at all, the operation is skipped
--query k=v, --header k=vAdded to every request (repeatable)
--timeout <d>Per-request timeout (default 30s)
--parallel <N>Run N operations at once. Results stay in spec order. Each operation gets its own copy of env/vars
--retries <N>Retry network errors and 5xx responses up to N times (backoff 250ms × attempt)
--bailStop after the first failed or errored operation; the rest are reported as skipped
--dry-runResolve every request without sending
--insecureSkip TLS certificate verification
--ca-cert <pem>Extra trusted CA certificates
--client-cert <pem> / --client-key <pem>Mutual TLS
--proxy <url>http, https or socks5 proxy (default: $HTTPS_PROXY/$HTTP_PROXY)
--no-redirects / --max-redirects <n>Return 3xx responses as-is / limit redirect chains (default 10)
--max-body <size>Maximum response body, e.g. 10MB (default 50MB)

With --parallel 1 (the default), vars.set() in one operation's script is visible to the next operations.

Scripts ​

--script <file>, --no-contract, --script-timeout <d>, --offline, --reload, --frozen-lockfile, --allow-import <hosts>. See Test Scripts.

Output ​

FlagDescription
--output prettyHuman-readable log, printed as operations complete (default)
--output jsonOne JSON report on stdout (nothing else is printed)
--output junitJUnit XML: one <testsuite> per operation, one <testcase> per check
--output tapTAP version 14, one test point per check
--output-file <path>Write the --output report to a file; stdout keeps the pretty log
--bodies failed|all|noneRequest/response bodies in JSON (default: only for operations that did not pass; truncated at 64 KiB)

Sensitive request headers (Authorization, Cookie, anything containing token, secret, password or api-key) are redacted in reports.

Examples ​

bash
# Read-only pass over the whole API
lazyapi run api.yml --server https://staging.example.com

# CI: everything, JUnit for the CI UI, pinned imports
lazyapi run api.yml --methods all --param id=42 --frozen-lockfile --output junit --output-file report.xml

# Agent: machine-readable, fast
lazyapi run api.yml --tag users --parallel 8 --output json
